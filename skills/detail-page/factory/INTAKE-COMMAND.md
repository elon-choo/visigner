# /visigner:intake 커맨드 설계 초안

버전: `0.2.0` (G2.0 — G1.6 dry-run 결함 D1·D4·D5 반영. 변경 이력은 §5, 미반영 보류 안건은 §6)
상태: **커맨드 실물 미구현.** 이 문서는 인입 플로우의 파일 계약과 게이트 경계를 정의하는 설계 SSOT 초안이다. 지금은 AI 세션 안에서 사람이 이 계약대로 단계를 밟는 **반수동 플로우**이며, 반복이 검증된 뒤 커맨드로 승격한다.
전제: `SECTION-SCHEMA.md 1.0.0`, `COMPOSITION-GRAMMAR.md 1.0.0`, 모듈 카탈로그 `v3/modules/`.

## 0. 원칙

1. **사람 게이트 3개 고정**: ①브리프 컨펌 ②플랜 컨펌 ③최종 검수. 게이트를 통과하지 않은 산출물은 다음 단계의 입력이 될 수 없다(fail-closed).
2. **컨펌된 산출물만 흐른다**: 각 산출 파일은 status 헤더(`draft | confirmed | rejected`)를 가지며, `confirmed`는 사람만 기록한다.
3. **콘텐츠 사실성**: 클라이언트가 제공하지 않은 수치·인용·역량 주장을 생성하지 않는다. 없는 재료는 `재료 없음 — 클라이언트에 요청`으로 표기하고 질문 목록으로 되돌린다.
4. **카탈로그 우선**: 섹션 플랜은 카탈로그의 실존 모듈에서 고른다. 없는 타입은 `TBD` 로 정직 표기한다 — TBD를 즉석 제작으로 메우지 않는다.

## 1. 디렉터리·파일 계약

```text
intake/<client-slug>/
├── input.md                # Step 0 원자료 (사람 작성/수집)
├── brief.md                # Step 1 산출 (AI) → 게이트 1 대상
├── section-plan.md         # Step 2 산출 (AI) → 게이트 2 대상
├── composition.json        # Step 3 산출 (S4 composer) — 계약만 정의됨
├── slots/<section>.json    # Step 3 슬롯 값 (S4) — 계약만 정의됨
├── gate-log/               # Step 4 검인 로그 (exit code 포함 실행 기록)
└── delivery-checklist.md   # Step 5 게이트 3 대상 (사람 서명)
```

`<client-slug>`는 소문자-하이픈. `intake/`는 클라이언트 정보를 담으므로 커밋 대상이 아니다(gitignore 대상 — 배선은 실클라이언트 첫 사용 전 필수).

## 2. 단계별 계약

| 단계 | 입력 | 처리 주체 | 출력 | 게이트 |
|---|---|---|---|---|
| 0. 입력 수집 | 클라이언트 대화·자료 | **사람**(수집) + AI(정형화 보조) | `input.md` | 없음 |
| 1. 브리프 생성 | `input.md` | **AI** | `brief.md` (status: draft) | **게이트 1: 사람 브리프 컨펌** |
| 2. 섹션 플랜 제안 | confirmed `brief.md` + `v3/modules/` 카탈로그 | **AI** | `section-plan.md` (status: draft) | **게이트 2: 사람 플랜 컨펌** |
| 3. 조립 | confirmed `section-plan.md` | **composer (S4 실물 예정)** | `composition.json` + `slots/*.json` + 렌더 | 없음(기계) |
| 4. 검인 | Step 3 산출 | **스크립트** | `gate-log/` | 없음(기계, fail-closed) |
| 5. 납품 검수 | 렌더 + gate-log | **사람** | `delivery-checklist.md` | **게이트 3: 사람 최종 검수** |

### Step 0 — 입력 수집 (반수동)

사람이 클라이언트에게서 받은 원자료를 `input.md`에 모은다. 형식 자유. AI는 받아쓰기·정형화를 도울 수 있으나 내용을 만들지 않는다.

### Step 1 — 브리프 생성 (자동)

`input.md`를 아래 고정 구조의 `brief.md`로 정형화한다.

```markdown
---
status: draft
client: <slug>
---
## 클라이언트 개요        # 업종·규모·현재 상태 — input.md에 있는 사실만
## 대상 방문자            # 누가 이 페이지에 오는가
## 페이지 목표            # 주 행동 정확히 1개 + 보조 행동 0–1개
## 톤·무드               # D5: 클라이언트 표현(원문 그대로) 칸 + 시스템 해석 칸 — 두 칸 분리
## 콘텐츠 재료 인벤토리    # 보유 재료 목록: 텍스트/미디어/증거, 각각 출처 표기
## 제약·미보유            # 없는 재료, 기한, 금지 사항
## 열린 질문              # 필수 정보 체크리스트 미충족 항목 → 클라이언트 질문
```

`톤·무드` 절 규칙 (D5): **클라이언트 표현** 칸에는 원자료의 톤 발화를 따옴표 원문 그대로 적는다(각색·요약 금지). **시스템 해석** 칸에는 그 발화를 변형축 언어(특히 artDirection·motion 후보)로 번역한 결과와 번역 근거를 적는다 — 해석은 반드시 표현 칸의 원문에 소급 가능해야 한다. 톤 발화가 없으면 표현 칸에 `발화 없음`을 표기하고 해석 칸을 비운다(원문 없는 해석 생성 금지).

**필수 정보 체크리스트** (하나라도 미충족이면 `열린 질문`에 기재하고 draft 유지):
①업종·가게명 ②주 행동 1개(무엇을 하게 할 것인가) ③주 행동의 목적지(연락 수단·폼·링크) ④핵심 소개 텍스트 재료 ⑤주 미디어 자산 유무 ⑥증거 재료(후기·수치·인증 — proof 섹션 가능 여부 결정) ⑦법적·연락처 정보.

### 게이트 1 — 브리프 컨펌 (사람)

사람이 `brief.md`를 읽고 직접 수정한 뒤 `status: confirmed`로 바꾼다. 열린 질문이 남아 있으면 confirmed 불가 — 답을 받아 반영하거나, 해당 재료 없이 진행함을 명시적으로 적은 뒤에만 confirmed.

### Step 2 — 섹션 플랜 제안 (자동)

confirmed `brief.md`와 카탈로그를 대조해 `section-plan.md`를 만든다. 구조:

```markdown
---
status: draft
brief: brief.md@confirmed
---
## 섹션 플랜 (읽기 순서)
| # | 타입 | 모듈 | 변형축 | 선택 근거 (브리프 참조) | 슬롯 재료 매핑 |
## 문법 사전 점검         # 커버리지 수치(n/m) 필수 표기 + 미검증 구간 명시 (D1)
## 재료 공백              # `재료 없음 — 요청` 항목 총괄
```

규칙:
- **모듈** 열은 카탈로그 실경로(예: `modules/hero/neutral-split-hero`) 또는 `TBD(<type>)`.
- **선택 근거**는 브리프의 어느 절에서 왔는지 적는다. 근거 없는 섹션은 플랜에 넣지 않는다. artDirection 변형축 선택의 근거는 브리프 `톤·무드` 절(시스템 해석 칸)을 지목한다 — 톤·무드 절에 소급되지 않는 artDirection 선택 금지 (D5).
- **슬롯 재료 매핑**은 필수 슬롯마다 브리프 재료 인벤토리의 항목을 가리킨다. 재료가 없으면 `재료 없음 — 요청`. 필수 슬롯이 재료 없음이면 그 섹션은 **조립 불가 상태**임을 플랜에 명시한다.
- **증거 재료 0건 proof 규칙 (D4, fail-closed)**: 섹션 근거(신뢰 형성)가 있어도 브리프 재료 인벤토리의 증거 재료(후기·수치·인증 등)가 **0건으로 확정**이면 proof 섹션은 플랜에 넣지 않는다(자동 제외). 대신 `재료 공백` 절에 `proof: 재료 요청` 항목으로 기록하고, 재료가 실제로 도착해 브리프가 재컨펌된 뒤에만 플랜 개정으로 추가한다. 증거를 지어내 채우는 것(가상 후기·수치·인증 생성)은 어떤 경우에도 금지. 0.1.0의 "재료 없음 표기 후 게이트 2에서 유지/제외 결정" 경로는 이 규칙으로 대체된다 — 재료 0건 proof는 사람 결정 대상이 아니라 자동 제외 대상이다.
- **문법 사전 점검**: 인접 다양성·아키타입 중복·full-bleed 규칙·모션 밀도를 카탈로그 모듈 구간에 대해 점검한다. `TBD` 섹션은 `module.json`이 없어 기계 점검 불가 — 해당 인접쌍은 `미검증`으로 명시한다(추정으로 통과 처리 금지). **커버리지 수치 필수 표기 (D1)**: `문법 점검 커버리지: n/m` 한 줄을 반드시 남긴다. m = 플랜 인접쌍 전체 수(섹션 수 − 1), n = grammar-lint가 **플랜의 실제 인접 순서 그대로** 점검한 쌍 수. TBD 포함 쌍은 n에 불산입. 카탈로그-only 축약 경로 보조 점검은 실제 플랜 인접이 아니므로 n에 불산입하고 별도 줄로 기록한다 — TBD 탓 미점검 쌍이 수치 뒤에 숨지 않게 한다.

### 게이트 2 — 플랜 컨펌 (사람)

사람이 섹션 구성·순서·변형 선택을 확정한다. TBD 섹션의 처리(대기/타 모듈 대체/섹션 제외)는 여기서 사람이 결정한다.

### Step 3 — 조립 (자동, S4에서 실물)

confirmed `section-plan.md` → `composition.json`(COMPOSITION-GRAMMAR 매니페스트 형식) + 섹션별 슬롯 값 파일 → composer가 결정론적으로 조립·렌더한다. LLM의 역할은 플랜 단계의 **선택**까지이고, 조립 자체는 스크립트다. 슬롯 값 파일의 상세 스키마는 S4에서 확정한다(현재 미정).

### Step 4 — 검인 (자동)

기존 게이트 체인을 그대로 실행하고 로그를 `gate-log/`에 남긴다:

```bash
node v3/scripts/section-validate.js <참조 모듈 전체>   # exit 0 필수
node v3/scripts/grammar-lint.js intake/<slug>/composition.json  # exit 0 필수
# + 각 모듈 gateProfile 항목(media alt, reduced-motion 등)
```

실패 시 자동 재수행은 최대 2회. 그래도 실패면 사람에게 반환한다(fail-closed) — 게이트를 낮춰서 통과시키지 않는다.

### 게이트 3 — 납품 체크리스트 (사람)

`delivery-checklist.md` 항목 전체를 사람이 확인·서명해야 납품이다:

- [ ] 렌더 시각 확인(현 버전은 데스크톱 기준 — 반응형은 스키마 v1 범위 밖임을 인지하고 확인)
- [ ] 모든 슬롯 값이 브리프 재료 인벤토리로 소급됨(생성된 사실 주장 0)
- [ ] 더미/placeholder 텍스트 노출 0
- [ ] CTA 목적지 실값·작동 확인
- [ ] 법적 문구·연락처가 클라이언트 확인값
- [ ] `gate-log/`에 exit 0 로그 실재
- [ ] 미디어 대체 텍스트 배선 확인

## 3. 자동/수동 경계 요약

| 자동(AI/스크립트) | 수동(사람) |
|---|---|
| 원자료 정형화, 브리프 초안, 질문 목록 생성 | 원자료 수집, 브리프 수정·컨펌(게이트 1) |
| 섹션 플랜 제안, 근거·재료 매핑, 문법 사전 점검 | 플랜 확정·TBD 처리 결정(게이트 2), 취향·방향 결정 전부 |
| 조립(S4)·검인 실행·재시도 | 검인 실패 초과 시 개입, 최종 검수·서명(게이트 3) |

## 4. 미결 (정직 표기)

- composer 실물과 슬롯 값 파일 스키마 — S4.
- `intake/` gitignore 배선 — 실클라이언트 첫 사용 전 필수.
- TBD 섹션 포함 플랜의 문법 점검 공백 — 카탈로그 확장(S3)으로 좁혀지는 구조적 한계. 0.2부터 커버리지 `n/m` 수치로 가시화(D1)되나 공백 자체는 S3 전까지 남는다. G1.6·G2.0 dry-run 결과 참조.
- 커맨드 패키징(`/visigner:intake` 실등록) — 반수동 반복 검증 후.

## 5. 변경 이력

### 0.1.0 → 0.2.0 (G2.0 — G1.6 dry-run 결함 반영)

- **D1 반영** (§2 Step 2 규칙 + section-plan.md 구조 주석): 문법 사전 점검에 `문법 점검 커버리지: n/m` 수치 필수 표기 규칙 추가 — TBD 모듈 탓 미점검 인접쌍이 서술 뒤에 숨지 않게. n 산입 기준(실제 인접 순서 그대로 점검한 쌍만, 축약 경로 보조 점검 불산입) 명문화.
- **D4 반영** (§2 Step 2 규칙): 증거 재료 0건 확정 proof는 플랜 자동 제외 + `재료 공백`에 `proof: 재료 요청`으로 fail-closed 전환. 지어내기 금지 명문화. 0.1.0의 "근거 없는 섹션 제외" 원칙과 "재료 없음 표기 후 게이트 2 결정" 경로 사이 충돌 해소(후자 폐기).
- **D5 반영** (§2 Step 1 구조 + Step 2 선택 근거 규칙): brief.md 고정 구조에 `톤·무드` 절 신설 — 클라이언트 표현(원문 그대로) 칸과 시스템 해석 칸 분리. artDirection 변형축 선택 근거를 이 절로 소급 가능하게 강제.
- **D3 미반영(의도)**: "미디어 없는 hero 변형 신설"은 카탈로그 방향 결정(오너 안건) — §6 보류 안건에 기록만, 계약 무변경.
- D2(footer-band 모듈 0종)는 INTAKE 계약 결함이 아니라 S3 카탈로그 우선순위 신호 — 본 문서 무변경(G3.2 노트로 이관, G1.9 Stage 1 리뷰 판정).

## 6. 보류 안건 (오너 카드 대상 — 본 버전 미반영)

- **D3 — hero.media 필수 vs 소상공인 사진 부재 충돌.** 초기 인입의 흔한 상태(사진 미보유)가 곧바로 hero 조립 불가를 만든다. 선택지: ① 사진 도착까지 hero 조립 불가 유지(현행) ② 미디어 없는 hero 변형 신설(카탈로그 방향 변경). 취향·방향 판단이므로 INTAKE 계약이 임의로 정하지 않는다 — 오너 카드 결정 전까지 현행(①) 유지.
