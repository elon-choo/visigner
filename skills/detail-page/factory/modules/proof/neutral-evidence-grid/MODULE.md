# neutral-evidence-grid

타입: `proof` · 규격: SECTION-SCHEMA `1.0.0` · 게이트: `section-baseline-v1`

## 1. 왜 이 방식인가

proof 타입의 필수 파트(주장 제목·증거 묶음·출처)를 헤더 스택 → 2컬럼 카드 `grid` → 출처 각주 순으로 풀었다. 증거 항목을 동등 위계의 카드로 병렬해 항목 간 순서 함의를 없앴다 — `rail`(가로 흐름)이나 순번 목록은 앞 항목에 가중치를 주므로 배제. 각 항목이 `card` 배경 + 최소 그림자(e1)를 가져 개별적으로 "검사 가능한 단위"로 읽힌다.

`artDirection: data-led`는 이 모듈의 성격 선언이다: 증거는 장식이 아니라 검사 대상이므로, 시각 처리를 항목 구획(카드) 이상으로 올리지 않는다. 카탈로그에서의 역할은 **proof 기준형**이다.

## 컬렉션 아이템 구조 (`proofItems`, 2–6개)

이 버전에서 확정하는 아이템 계약:

- 아이템 = 단일 필드 객체 `{ "text": string }`. `text`는 검사 가능한 관찰·사실 한 문장, 권장 8–140자(공백 포함).
- 렌더러는 아이템당 `<li>` 하나를 컨테이너(`data-slot="proofItems"`가 앵커된 `<ul>`) 안에 반복 생성한다.
- `text`에 수치·인용이 들어가면 그 출처가 `sourceNote` 또는 문장 안에 있어야 한다. 출처 없는 수치 주장은 주입 단계에서 거부한다(모듈이 아니라 인입 플로우의 책임이지만, 계약은 여기 명시한다).
- 아이콘·수치 강조·인용자 표기 같은 리치 구조는 v1 범위 밖 — 필요하면 후속 proof 변형 모듈에서 별도 아이템 계약으로 확정한다.

## 2. 의존

- (a) 규격: `schemaVersion 1.0.0`. 기본값이 `card-contained`(contained)라 이음새 규칙에서 자유로운 편이다 — full-bleed 섹션 사이의 완충으로 쓰기 좋다.
- (b) 토큰: 표면·텍스트·선 범주와 글꼴(display+body), 여백·활자 스케일, `--radius-md`, `--shadow-e1`. **행동색을 전혀 소비하지 않는다** — 60/30/10 배분에서 행동색 예산을 쓰지 않는 섹션이라는 것이 조성 시 이 모듈의 장점이다. 특이 소비: 카드 테두리 두께 `--space-4`(raw px 금지 우회 관례).
- (c) 다른 모듈: 없음(독립).

## 3. 변경 파급

- 아이템 구조에 필드를 추가하면(예: 인용자) → 위 "컬렉션 아이템 구조" 계약과 렌더러(S4) 반복 생성 규칙을 함께 개정해야 한다. `module.json`은 컬렉션 개수 범위만 계약하므로 변경 불요. 재검증: `section-validate` + 렌더러 생기면 렌더 스냅샷.
- `proofItems` 개수 범위(2–6)를 바꾸면 → SECTION-SCHEMA 공용 슬롯 표 개정 사안이다. 단독 변경 금지.
- 카드 grid를 1컬럼/3컬럼으로 바꾸면 → CSS `grid-template-columns`와 함께, 최소 개수 2에서의 시각 균형(빈 셀)을 다시 봐야 한다. `layoutArchetype` 값 자체는 `grid` 유지라면 lint 영향 없음 — 시각 검토로만 잡힌다.
- `sourceNote`를 필수로 승격하면 → `module.json`의 `required`와 스키마 표(선택 슬롯)의 불일치가 생긴다. 스키마 개정과 함께만.

## 4. 코치 코멘트

- 카드 테두리 `--space-4`는 raw `px` 금지 계약의 우회 관례다. `1px`로 "정상화"하면 검증기가 막는다.
- 2컬럼 고정 grid에서 아이템이 홀수 개(3·5)면 마지막 행에 빈 셀이 남는다. 처리(span·중앙 정렬)는 v1 범위 밖의 의도된 공백 — 변형 시 여기부터 확인. 미검증 — 실렌더 확인 전까지는 구조상 추론이다.
- 이 모듈은 `headline`이 `h2`다. hero 없이 페이지 최상단에 쓰면 제목 계층이 h2로 시작한다 — lint 미커버, 조성 시 사람 확인.
- 슬롯 값 주입 시 `body`·`sourceNote`는 선택이다. 값이 없을 때 빈 요소를 남길지 제거할지는 렌더러 계약 미정(S4) — 현재 템플릿은 placeholder 텍스트를 갖고 있으므로, 렌더러 전 단계에서 이 템플릿을 그대로 내보내면 더미 문장이 노출된다. 재현 시 가장 흔한 사고 지점.
