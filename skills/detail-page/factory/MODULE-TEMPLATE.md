# MODULE.md TMI 규격 확정본

버전: `1.1.0` (G4.0 보강 · G1.6 확정본 호환)
적용 범위: `v3/modules/<type>/<name>/MODULE.md`
상위 규격: `v3/SECTION-SCHEMA.md` §5.3 — 그 절이 예약한 "여섯 항목의 읽기용 목차"의 **내용 규격**을 이 문서가 확정한다.

## 변경 이력

- `1.1.0` (G4.0): G3.5 재현 공백을 반영해 선택 슬롯의 DOM 위치·생략 규칙, `density`·`motion`·`artDirection` 기본값, 컬렉션 내부 반복 구조를 필수 문서 항목으로 명시했다. 기존 `1.0.0`의 여섯 섹션 순서와 `pending-g1.6` TMI 상태는 유지한다.
- `1.0.0` (G1.6): 여섯 TMI 섹션과 컬렉션 아이템 구조 소절을 확정했다.

## 0. 공통 규칙

- MODULE.md의 독자는 **이 모듈을 처음 보는 다음 세션의 AI(또는 사람)**다. 그가 모듈을 재현·변형·교체할 때 코드만 봐서는 알 수 없는 것(의도·경계·함정)을 적는다. 코드가 이미 말하는 것(슬롯 목록 나열, CSS 값 복사)은 중복하지 않는다.
- 중립성: 특정 제품·업종·클라이언트 맥락을 포함하지 않는다(SECTION-SCHEMA 서두와 동일 원칙).
- 판정 가능성: 모든 문장은 검사 가능하거나("~라서 ~를 골랐다") 정직한 미정 표기("미정 — <사유>")여야 한다. 아는 것처럼 쓰는 추정 금지.
- `module.json`의 `tmi` 블록은 이 버전에서 구조 예약(`pending-g1.6`) 그대로 둔다 — `section-validate.js`가 그 상태를 강제하며, 해제는 스키마 버전 업 사안이다. **TMI 내용의 원천은 MODULE.md다.**
- 아래 6개 섹션은 제목·순서 고정. 섹션 추가 금지. 해당 없음이면 비우지 말고 `없음 — <사유>`로 적는다.
- 선언된 선택 슬롯은 반드시 **선택 슬롯 DOM 위치** 표에서 landmark와 상대 위치를 확정한다. 값이 없을 때 요소를 제거하는지, 숨김 상태로 두는지, 대체 문구를 두는지도 함께 적으며 `미정`만으로 끝내지 않는다.
- `module.json.variants`의 `density`, `motion`, `artDirection`은 §1에서 정확한 enum 값과 기본값으로 명시한다. 세 축은 선택 이유가 짧더라도 생략하지 않으며, 근거가 없으면 `미검증 — <확인 방법>`으로 표시한다. `motion`이 `none`이 아니면 reduced-motion 처리와 gate 재판정 조건도 적는다.
- 컬렉션 슬롯을 가진 모듈은 **아이템 내부 구조를 §2(의존) 또는 §4(코치 코멘트)가 아닌 별도 소절 "컬렉션 아이템 구조"로 §1 뒤에 확정한다**(SECTION-SCHEMA §2.2 말미가 이 문서 계열로 위임한 사항). 아이템 shape, 반복 컨테이너·항목 요소, 각 필드의 DOM 매핑, 입력 순서, 범위 밖 구조를 모두 적는다.

## 1. 왜 이 방식인가 (설계 의도)

**작성 기준**
- 이 모듈이 담당하는 타입의 필수 파트를 **왜 이 배치·위계로** 풀었는지 적는다. 다른 합리적 대안(예: grid 대신 rail)을 버린 이유가 한 줄이라도 있어야 한다.
- 기본 변형축 5값 중 **선택에 이유가 있는 축만** 골라 설명한다(전 축 기계 나열 금지).
- 단, `density`, `motion`, `artDirection`은 이유가 짧거나 계약 기본값이어도 정확한 기본값을 별도 표로 기록한다. 값·근거·미검증 상태를 섞어 쓰지 않는다.
- 카탈로그 안에서의 역할(기준형인지, 특정 변형인지)을 한 줄로 적는다.

### 선택 슬롯 DOM 위치

선택 슬롯마다 다음 표를 채운다. `DOM 위치`는 landmark 또는 형제·부모와의 상대 위치로 쓴다. 선언했지만 실제 템플릿에 앵커가 없는 선택 슬롯은 허용하지 않는다.

| 슬롯 | DOM 위치 | 값이 없을 때 |
| --- | --- | --- |
| `<optional-slot>` | `<landmark> 안, <relative position>` | `<remove | hide | neutral fallback>` |

### 기본 변형축

| 축 | `module.json` 기본값 | 선택 근거 또는 미검증 표기 |
| --- | --- | --- |
| `density` | `<airy | standard | compact>` | `<근거>` |
| `motion` | `<none | reveal | stagger | scroll-linked>` | `<근거; none이 아니면 reduced-motion 조건>` |
| `artDirection` | `<typographic | editorial | product-ui | documentary | data-led | photographic>` | `<근거>` |

**좋은 예** — "증거 항목을 동등 위계 카드 grid로 나열해 항목 간 순서 함의를 없앴다. rail(가로 흐름)은 앞 항목에 가중치를 주므로 배제."
**나쁜 예** — "그리드가 모던하고 깔끔해서"(판정 불가 취향), "2컬럼 grid를 사용한다"(이유 없는 코드 반복).

## 2. 의존

**작성 기준** — 아래 세 층위를 고정 순서로 적는다.
- (a) **규격**: 따르는 `schemaVersion`과, 조립 시 걸리는 `COMPOSITION-GRAMMAR.md` 규칙 중 이 모듈에 특히 민감한 것.
- (b) **토큰**: 소비하는 semantic 토큰을 **범주 단위**로 적고(전량 기계 복사 금지), 관례에서 벗어난 특이 소비만 개별 명시한다.
- (c) **다른 모듈**: 없으면 "없음(독립)"을 명시한다. 있으면 방향(누가 누구를 전제하는지)까지.

**좋은 예** — "기본값이 `contrast-bleed`라 이음새 규칙(full-bleed 연속 금지·개수 상한)의 영향을 카탈로그에서 가장 크게 받는다."
**나쁜 예** — "여러 토큰을 사용한다"(검사 불가), CSS의 `var(...)` 전체를 그대로 옮겨 적기(코드 중복 — 변경 시 이중 관리 발생).

## 3. 변경 파급

**작성 기준**
- "X를 바꾸면 Y를 같이 바꿔야 한다" **쌍(pair)** 형식으로만 적는다. 최소 세 축을 다룬다: ①슬롯 변경 ②변형축 기본값 변경 ③구조/스타일 변경.
- 각 쌍마다 **재검증 명령**(`section-validate.js`, `grammar-lint.js`, 시각 검토)을 명시한다.
- 파급이 이 모듈 밖(스키마 표, 조성 fixture)으로 나가는 경우를 반드시 구분해 적는다 — 그것이 "전부 새로 만드는 사태"를 막는 항목이다.

**좋은 예** — "`layoutArchetype` 기본값을 바꾸면 CSS의 grid 정의를 함께 바꿔야 한다 — 축 값과 CSS는 자동 동기화되지 않는다. 변경 후 `section-validate` + 이 모듈을 참조하는 조성의 `grammar-lint` 재실행."
**나쁜 예** — "수정 시 여러 곳에 영향이 있으니 주의"(어디인지 없음), 재검증 명령 누락.

## 4. 코치 코멘트

**작성 기준**
- 다음 세션의 AI가 이 모듈을 (a) 재현할 때 (b) 변형할 때 (c) 슬롯 값을 주입할 때, 각각 걸리기 쉬운 함정을 적는다. 코드에서 자명한 것은 제외.
- "고치고 싶어 보이지만 고치면 안 되는 것"(검증기·규격이 강제하는 우회 불가 지점)을 우선 배치한다.
- 실측·규격 근거가 있는 것만 단정한다. 근거 없는 일반론("접근성에 유의")과 모델 감상 금지. 미확인 사항은 `미검증 — <확인 방법>`으로.

**좋은 예** — "테두리 두께에 `--space-4`를 쓴 것은 raw `px` 금지 계약 때문이다. '여백 토큰 오용'으로 보고 `4px`로 고치면 검증기가 막는다."
**나쁜 예** — "수정할 때 주의할 것"(무엇을?), "일반적으로 hero는 심플한 것이 좋다"(이 모듈 특정적이지 않음).

## 5. 100점 예시 링크

**작성 기준**
- 골드 렌더(게이트를 전부 통과하고 예시로 승격된 렌더)의 경로를 적는 자리다. 예약 경로 형식: `v3/renders/gold/<type>--<name>/`.
- **골드 렌더가 생기기 전에는** 정확히 다음 형식만 허용한다: `pending — 예약 경로: v3/renders/gold/<type>--<name>/`. 존재하지 않는 파일을 존재하는 링크처럼 적지 않는다.
- 승격 시 placeholder를 실경로로 교체하고, 승격 근거(게이트 로그 경로)를 한 줄 덧붙인다.

**좋은 예** — `pending — 예약 경로: v3/renders/gold/hero--neutral-split-hero/`
**나쁜 예** — 아직 없는 렌더에 실링크 문법으로 링크 걸기, "추후 추가"(경로 규칙 없는 미룸).

## 6. 출처

**작성 기준** — corpus 레코드 참조 형식은 `module.json.corpusSource`와 동일한 두 필드를 읽기용으로 서술한다.
- `recordId`: corpus-index.json `records[].id` 그대로.
- `sectionSpan`: `<capture_dir>/<tile 파일>#<관찰 구역>` — 확인된 tile과 구역 이름만. 수직 오프셋 맵이 없으면 좌표를 추정해 적지 않는다.
- 마지막 줄에 **가져온 것의 범위**를 명시한다: 구조 관찰(배치·위계·역할)만이며, 픽셀·카피·브랜드 요소 복제가 아님.

**좋은 예** — "recordId `stripe`, span `captures/app-ui/stripe/tile_00.png#proof`. 가져온 것은 '증거를 동등 카드로 병렬한다'는 구조 관찰뿐이다."
**나쁜 예** — 추정 좌표 범위 기입, 원본 사이트의 문구 인용.
